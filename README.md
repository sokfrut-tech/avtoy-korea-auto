# AVTOY KOREA — сайт и Telegram-бот

Исходный файл Cloudflare Worker: `worker.js`. Имя файла и папка проекта сохранены.

## Что умеет бот

Webhook-адрес после публикации Worker: `https://avtoy-korea-auto.sokfrut.workers.dev/telegram/webhook`

Команды:
- `/start` — приветствие и меню;
- `/help` — подсказка;
- `/countries` — Корея, Китай, ОАЭ;
- `/catalog` — как проходит подбор (это описание процесса, не живой каталог объявлений);
- `/contact` — сайт и канал;
- `/reply CHAT_ID текст` — ответ клиенту от имени бота, доступен только администратору.

Сообщения из личных чатов бот отправляет каждому настроенному администратору в личку. Сообщения из групп и каналов игнорируются. В уведомлении указывается Chat ID клиента для команды `/reply`. Заявки с сайта также отправляются администраторам по отдельности; ID группы использовать нельзя.

## Настройка перед запуском

В Cloudflare Workers → `avtoy-korea-auto` → Settings → Variables and Secrets добавьте:

- `TELEGRAM_BOT_TOKEN` — новый токен бота, сохранённый как Secret;
- `TELEGRAM_ADMIN_IDS` — личные числовые Telegram ID администраторов, через запятую (например, `123456789,987654321`). Используйте только положительные ID личных чатов; не указывайте ID группы;
- `TELEGRAM_CHAT_ID` — устаревшая совместимость для одного личного администратора. Отрицательные ID групп игнорируются;
- `TELEGRAM_WEBHOOK_SECRET` — отдельная случайная строка 1–256 символов из букв A-Z/a-z, цифр, подчёркивания и дефиса. Сохранить как Secret.

Не добавляйте токены в GitHub, исходный код, скриншоты или публичные сообщения. Если ранее токен публиковался в чате, сначала отзовите его у `@BotFather` и создайте новый.

После публикации Worker нужно зарегистрировать webhook у Telegram, передав:
- URL: `https://avtoy-korea-auto.sokfrut.workers.dev/telegram/webhook`
- `secret_token`: значение `TELEGRAM_WEBHOOK_SECRET`

Telegram webhook должен быть зарегистрирован именно с новым токеном бота. Без публикации Worker, секретов и регистрации webhook бот ещё не работает в Telegram.

### Обязательное хранилище заявок (REVIEWS)

Создайте KV namespace в Cloudflare Workers & Pages → KV (например, `AVTOY_REVIEWS`). Затем откройте Worker `avtoy-korea-auto` → Settings → Bindings → Add → KV namespace и задайте:

- Variable name: `REVIEWS`
- KV namespace: созданный namespace `AVTOY_REVIEWS`

Сохраните изменения и убедитесь, что binding доступен Worker. Без `REVIEWS` форма намеренно возвращает ошибку и не сообщает клиенту, что заявка принята. Не создавайте namespace заново при каждом обновлении: в нём хранятся заявки, статусы и опубликованные отзывы.

### Ограничение частоты заявок

В Cloudflare Dashboard откройте Security → WAF → Rate limiting rules и создайте правило для `POST /api/request` на домене Worker. Начальная настройка для защиты от спама: считать по IP-адресу, порог 5 запросов за 10 минут, действие Block на 10 минут. Перед сохранением проверьте, что правило применяется только к `POST /api/request`, а не ко всему сайту. Для webhook `/telegram/webhook` настройте отдельное правило с более высоким порогом, чтобы не блокировать штатные повторы Telegram.

Правило WAF — настройка аккаунта Cloudflare, оно не включается автоматически кодом из GitHub. После настройки проверьте отправку одной обычной заявки и повторный запрос с тестового клиента.

## Проверки и безопасность

- Секрет webhook проверяется по заголовку `X-Telegram-Bot-Api-Secret-Token`.
- Команда `/reply` доступна только личным ID из `TELEGRAM_ADMIN_IDS` (или одному положительному legacy ID).
- Групповые/канальные сообщения не обрабатываются и не получают ответы бота.
- Форма сайта использует `POST /api/request`; заявки отправляются каждому настроенному личному ID отдельно.
- Перед публикацией проверьте команды тестовым сообщением и отправку тестовой заявки.

## Резервные версии

Перед изменением `worker.js` создаётся копия в `versions/worker_YYYY-MM-DD_HH-MM-SS.js` (время Германии). Основной файл всегда называется `worker.js`.
