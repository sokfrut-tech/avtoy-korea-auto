# AVTOY KOREA — сайт и Telegram-бот

Исходный файл Cloudflare Worker: `worker.js`. Имя файла и папка проекта сохранены.

## Что умеет бот

Webhook-адрес после публикации Worker: `https://avtoy-korea-auto.sokfrut.workers.dev/telegram/webhook`

Команды:
- `/start` — приветствие и меню;
- `/admin` — меню и инструкция администратора (только в личном чате администратора);
- `/adminlink` — одноразовый код для защищённой панели управления сайтом;
- `/site` — список опубликованных материалов: можно изменить текст конкретного объявления или снять публикацию с сайта;
- `/log` — журнал действий администраторов;
- `/help` — подсказка;
- `/countries` — Корея, Китай, ОАЭ;
- `/catalog` — ссылка на актуальный каталог автомобилей на сайте.
- `/contact` — сайт и канал;
- `/reply CHAT_ID текст` — ответ клиенту от имени бота, доступен только администратору.

Сообщения клиентов из личных чатов бот отправляет каждому настроенному администратору в личку. Обычные сообщения из групп не пересылаются. В настроенной группе отзывов (`TELEGRAM_REVIEW_GROUP_ID`) бот принимает только медиа, отправленные администратором, и передаёт их администраторам в личку для ручной модерации. Администратор также может отправить фото или видео прямо боту в личный чат: бот создаст карточку с кнопками «Опубликовать» / «Не публиковать»; публикация на сайте не происходит автоматически. Сообщения с командой `/review` в этой группе также проходят модерацию. Публикации канала `@avtoYkorea` можно передавать на импорт администраторами. В уведомлении о личном сообщении указывается Chat ID клиента для команды `/reply`; также можно ответить непосредственно Reply на уведомление бота. В `/site` у каждой публикации доступны отдельные действия: редактировать текст (команды `ЗАМЕНИТЬ: старый => новый`, `УДАЛИТЬ: фрагмент`, `ДОБАВИТЬ В КОНЕЦ: текст`) и снять с сайта с подтверждением. Также есть браузерная панель `https://avtoy-korea-auto.sokfrut.workers.dev/admin`: администратор получает одноразовый 8-значный код командой `/adminlink` в личном чате бота. Код действует 5 минут и используется один раз; веб-сессия действует 8 часов. Редактирование опубликованного текста не меняет фотографии или другие объявления. Заявки с сайта также отправляются администраторам по отдельности; ID группы использовать нельзя.

## Настройка перед запуском

В Cloudflare Workers → `avtoy-korea-auto` → Settings → Variables and Secrets добавьте:

- `TELEGRAM_BOT_TOKEN` — новый токен бота, сохранённый как Secret;
- `TELEGRAM_ADMIN_IDS` — личные числовые Telegram ID администраторов, через запятую (например, `123456789,987654321`). Используйте только положительные ID личных чатов; не указывайте ID группы;
- `TELEGRAM_CHAT_ID` — устаревшая совместимость для одного личного администратора. Отрицательные ID групп игнорируются;
- `TELEGRAM_WEBHOOK_SECRET` — отдельная случайная строка 1–256 символов из букв A-Z/a-z, цифр, подчёркивания и дефиса. Сохранить как Secret.

Не добавляйте токены в GitHub, исходный код, скриншоты или публичные сообщения. Если ранее токен публиковался в чате, сначала отзовите его у `@BotFather` и создайте новый.

После публикации Worker нужно зарегистрировать webhook у Telegram, передав:
- URL: `https://avtoy-korea-auto.sokfrut.workers.dev/telegram/webhook`
- `secret_token`: значение `TELEGRAM_WEBHOOK_SECRET`

Telegram webhook должен быть зарегистрирован именно с новым токеном бота. Без публикации Worker, секретов и регистрации webhook бот ещё не работает в Telegram.

### Обязательное хранилище заявок (REVIEWS)

Создайте KV namespace в Cloudflare Workers & Pages → KV (например, `AVTOY_REVIEWS`). Затем откройте Worker `avtoy-korea-auto` → Settings → Bindings → Add → KV namespace и задайте:

- Variable name: `REVIEWS`
- KV namespace: созданный namespace `AVTOY_REVIEWS`

Сохраните изменения и убедитесь, что binding доступен Worker. Без `REVIEWS` форма намеренно возвращает ошибку и не сообщает клиенту, что заявка принята. Не создавайте namespace заново при каждом обновлении: в нём хранятся заявки, статусы и опубликованные отзывы.

### Ограничение частоты заявок

В Cloudflare Dashboard откройте Security → WAF → Rate limiting rules и создайте правило для `POST /api/request` на домене Worker. Начальная настройка для защиты от спама: считать по IP-адресу, порог 5 запросов за 10 минут, действие Block на 10 минут. Перед сохранением проверьте, что правило применяется только к `POST /api/request`, а не ко всему сайту. Для webhook `/telegram/webhook` настройте отдельное правило с более высоким порогом, чтобы не блокировать штатные повторы Telegram.

Правило WAF — настройка аккаунта Cloudflare, оно не включается автоматически кодом из GitHub. После настройки проверьте отправку одной обычной заявки и повторный запрос с тестового клиента.

## Проверки и безопасность

- Секрет webhook проверяется по заголовку `X-Telegram-Bot-Api-Secret-Token`.
- Команда `/reply` доступна только личным ID из `TELEGRAM_ADMIN_IDS` (или одному положительному legacy ID).
- Групповые/канальные сообщения не обрабатываются и не получают ответы бота.
- Форма сайта использует `POST /api/request`; заявки отправляются каждому настроенному личному ID отдельно.
- Перед публикацией проверьте команды тестовым сообщением и отправку тестовой заявки.

## Резервные версии

Перед изменением `worker.js` создаётся копия в `versions/worker_YYYY-MM-DD_HH-MM-SS.js` (время Германии). Основной файл всегда называется `worker.js`.


## Обязательные правила обработки фото отзывов

1. В массиве Telegram `PhotoSize[]` нельзя выбирать фотографию по позиции в массиве. Для каждого снимка выбирайте rendition с максимальной площадью `width × height`; при равной площади используйте больший `file_size`. Если размеры отсутствуют, используйте `file_size`, а исходный порядок — только как последний tie-breaker.
2. Сохраняйте вместе с `file_id` поля `file_unique_id`, `width`, `height` и `file_size`, если Telegram их прислал. Не заменяйте оригинальный `file_id` ссылкой на превью или уменьшенную копию.
3. Внутри одного отзыва/альбома удаляйте повторную доставку одного и того же Telegram media по `file_unique_id` (с fallback на `file_id`). Сохраняйте все разные снимки и порядок исходного альбома.
4. Не удаляйте одинаковые снимки между разными отзывами автоматически: клиент может намеренно использовать одну фотографию в разных публикациях. Между отзывами дедупликация допускается только после отдельного подтверждения владельца.
5. Публичная галерея должна показывать один элемент на один сохранённый снимок; не создавать дополнительные копии DOM. Для фото используйте `object-fit: contain`, не обрезайте и не подменяйте оригинал миниатюрой.
6. Ответы `/api/review-media/...` не должны кэшировать содержимое по нестабильному индексу альбома: используйте `Cache-Control: no-store`, пока URL не содержит версию конкретного media.
7. Перед публикацией администратор должен видеть полный состав альбома и число снимков. После публикации API должно отдавать ровно сохранённые уникальные элементы данного отзыва.
8. Администраторский альбом из группы отзывов должен иметь один `media_group_id` → одну запись импорта → одну карточку модерации. Все части альбома объединяйте последовательно; не запускайте для одного сообщения два независимых пути создания отзыва.
9. Любое изменение Telegram photo intake, album merge, API mapping или gallery rendering сопровождайте регрессионным тестом: переставленный порядок PhotoSize, разные разрешения, повтор webhook, повторный file_id/file_unique_id, несколько снимков альбома и отдельные отзывы с намеренно повторяющимися фотографиями.
